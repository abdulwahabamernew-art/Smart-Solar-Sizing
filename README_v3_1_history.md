# Smart Solar Sizing v3.1 — المخزون والتكلفة التجريبية

## ما الجديد

- محرك v3 السابق كما هو، مع استيراد موحد لقواعد المخزون الثلاث.
- 85 سجلًا محفوظًا بمصدره وصفه وحقوله الأصلية: 23 + 26 + 36. هذه ليست 85 منتجًا فريدًا؛ قد تتكرر الموديلات بين اللقطات.
- 7 مجموعات بأسماء موديلات متطابقة ولها اختلافات في بعض القيم. التقرير غير شامل للأسماء المختلفة التي قد تشير للمنتج نفسه.
- عدم جمع كميات المخزون عبر المصادر وعدم اعتبار Item_ID معرفًا عالميًا.
- فصل قدرة البطارية Wh عن قدرة الإنفرتر/الألواح W، وعدم تخمين جهد AC أو نطاق البطارية من حقول الجهد الملتبسة.
- ربط مثال الأحمال من v3 بمسودة حسابية للكميات والأسعار باستخدام مصدر واحد صريح ذي 26 صنفًا.
- 29 اختبارًا: 17 للمحرك و12 للمخزون والمسودة والتحويل النقدي.

## التشغيل

Python 3.9 أو أحدث؛ لا مكتبات إضافية. من داخل مجلد الحزمة:

```bash
python -m unittest discover -s tests -v
python demo.py
python run_inventory_demo.py
```

في Colab استخدم الدفتر `01_Inventory_and_Draft_Colab.ipynb` الذي يُحمّل هذه الحزمة تلقائيًا ويحفظ مجلدًا مستقلًا. لا يستبدل مجلد v3 السابق.

## ملفات المرحلة الجديدة

- `solar/inventory.py`: الاستيراد والتدقيق والقائمة التجارية الأولية وحساب الكميات والتكلفة.
- `run_inventory_demo.py`: يعيد بناء JSON من لقطات المصدر ثم يشغل مثالًا واضح الافتراضات.
- `outputs/inventory_normalized.json`: السجلات الموحدة مع الحقول الأصلية والبيانات الناقصة.
- `outputs/inventory_audit.json`: أعداد المصادر واختلافات الموديلات.
- `outputs/commercial_draft_example.json`: مدخلات المثال واحتياجه والبنود وتكلفتها.
- `tests/test_inventory.py`: اختبارات الاستيراد والوحدات والكميات والأسعار والحالات المرفوضة.

## ما تعنيه المسودة

المثال يستخدم الأحمال الافتراضية: ثلاجتان و3 شاشات و10 لمبات ومكيفان، PSH=6.2. إجمالي الطاقة 24660Wh/day. هذه مدخلات تجربة وليست وصفًا مؤكدًا لعميل.

تختار المسودة أقل تكلفة حسابية للألواح تكفي قدرتها المعلنة، وإنفرترًا واحدًا تكفي قدرته المعلنة مع الفاز المطلوب. لا تُستنتج إمكانات توازي الإنفرترات من جمع القدرات.

عدد الألواح فيها حد أدنى من ميزانية الطاقة، وقد يتغير بعد حساب السلاسل. هذه ليست تركيبة معتمدة، ولا عرض سعر مكتملًا. لا تُصدر تلقائيًا للعميل. التيارات ونطاقات الجهد والإقلاع والتوصيل والحماية لم تُعتمد.

مثال التشغيل الحالي: 12 لوح 450W بقيمة 1020USD، وإنفرتر 5000W بقيمة 560USD؛ مجموع البنود 1580USD. الأسعار والكميات من لقطة المصدر القديمة، وليست أسعار سوق حالية. لا يشمل المجموع البطاريات أو القواعد أو الحماية أو الكابلات أو التركيب أو النقل أو الضرائب.

للبطارية، تستخدم الدالة عند طلبها طاقة الليل وDoD المعلن لكل موديل. تستبعد اختلاف جهد البطارية الاسمي المعلن عن جهد ناقل الإنفرتر منخفض الجهد، ولا تعيد بناء نطاق HV بالتخمين. حتى مع تطابق الجهد الاسمي يظل BMS وقدرة التفريغ ومخطط التوصيل غير موثق.

تُدخل أسعار الصرف اختياريًا من المستخدم بوحدة عدد وحدات العملة لكل دولار، مع تاريخ مرجعي إلزامي. لا توجد أسعار صرف مباشرة أو ربح/خصومات/ضرائب ضمنية.

## البيانات التي ما زالت ناقصة

لا يوجد أي سجل مؤهل هندسيًا تلقائيًا في البيانات القديمة. نحتاج Datasheet للموديل الدقيق يوضح: جهد AC، مجال البطارية وتوافق BMS، قدرة الإقلاع ومدتها، MPPT min/max وبدء التشغيل، أقصى جهد DC، التيار التشغيلي والقصر لكل مدخل وعدد المداخل؛ وللألواح Isc وImp ومعاملات الحرارة. تُحفظ القيم الملتبسة تحت legacy/raw ولا تُحوَّل إلى حقائق.

البيانات مأخوذة من نسخ المصادر المقروءة في المرحلة السابقة، وليست مزامنة مباشرة مع Drive. لا تعدّل هذه الحزمة قواعد البيانات الأصلية. المحرك لا يحوّل السجلات غير الموثقة إلى توصيات هندسية مقبولة.

## التالي

استكمال مواصفات مجموعة صغيرة من المكونات أولًا، وربطها بمصمم السلاسل واختبار تركيب متوافق، ثم حساب البطاريات وBOM مكتمل وتقرير عربي. بعد تثبيت هذا المسار ننقل المحرك إلى Dart وFlutter.
